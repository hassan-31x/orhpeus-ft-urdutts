# ASLP implementation trace and UrduTTS adaptation

The training files and main Kaggle notebook in `../orpheus-ft-aslp/` were reviewed. Evaluation, presentation, grading and report folders are outside this work. The old `finetune_aslp_10h.py` is an earlier Colab notebook exported as Python: it mounts Drive, has notebook shell syntax, prepares ASLP manifests, encodes SNAC and trains LoRA. The active Kaggle path is the substantially more robust `finetune_aslp_50h.py` plus its helper modules.

## Original execution path

1. `kaggle_run.ipynb` clones a commit, checks GPU/credentials, creates a dedicated environment, constructs JSON config, and launches training as a subprocess. Its current ASLP settings explicitly seed epoch 2 from a finished epoch 1 with `INIT_FROM_RUN`; this is different from interruption resume. It expects attached ASLP files and has a Drive fallback.
2. `setup_kaggle.py` creates a venv inheriting system CUDA packages and constrains installed torch/vision/audio/triton/xformers versions. `check_environment.py` checks only the active project dependency graph and tests audio/Parquet, optionally a CUDA attention backward pass. This avoids unrelated Kaggle package conflicts blocking training.
3. Training CLI merges defaults, JSON and CLI overrides, validates settings, takes a per-run POSIX lock, and preflights storage. `HuggingFaceStore` requires a private model repo, tests upload/readback and redacts credential diagnostics. Audit mode stops before model loading. Training restores the remote run before processing audio.
4. ASLP `find_data` discovers prepared CSVs, or downloads/extracts a Drive ZIP safely. `audit_data` cleans text with NFC/whitespace/control handling, checks Urdu script, validates 24 kHz mono PCM16 WAVs, rejects silence/nonfinite signals, and detects duplicate paths/audio hashes across partitions. The first valid occurrence wins in train→validation→test order. Exclusions and retained hours are recorded.
5. Model and SNAC revisions are resolved and saved. Tokenizer vocabulary must cover the Orpheus special tokens and all seven 4,096-entry SNAC token ranges. Prompts use human/AI/speech delimiters and Urdu text without invented speaker/emotion labels.
6. `encode_data` encodes 24 kHz audio using `hubertsiuzdak/snac_24khz`. Three codec streams expand into seven interleaved tokens per coarse frame, each with its own codebook offset. Defaults preserve all frames and compute loss on the complete prompt/audio sequence. Context overflow excludes the complete pair rather than mismatching cropped speech and full text.
7. Token caches are 100-row Parquet chunks, with row identity, SHA-256 and exclusion metadata. Valid chunks survive interruption, are restored from the Hub, and are not repeatedly uploaded. Fingerprints include data, vocabulary, revisions, packages and token-producing source. Parsed-source comparison permits reuse after compatible reporting-only changes.
8. Training loads the original base in 4-bit with Unsloth and attaches rank-32/alpha-64 LoRA to attention and MLP projections. Defaults are microbatch 1, accumulation 8, LR 1e-4, cosine schedule, 3% warmup, AdamW, one epoch, seed 3407. A forward/backward memory probe can exclude long rows before optimization, freezing the retained order for later resume.
9. Trainer saves optimizer/scheduler/RNG state as well as adapters. Callbacks seal files with hashes, upload checkpoints before optional synthesis, log metrics and request an optimizer-boundary stop near the session budget. JSONL is canonical; TensorBoard, plots, generation and validation can fail without losing safely saved training state.
10. Hub snapshots use direct files and an atomic pointer commit, avoiding a full local tar copy. Restore verifies every file and checkpoint seal. Upload failures are queued with cooldown. Disk budgeting can prune older verified checkpoints; one failed disk-full save retries while weights remain in memory. Heartbeats publish stage and stack/log evidence independently of notebook output.
11. A finished run exports its adapter through hardlinks where possible, evaluates validation loss, records completion and backs up again. A repeated completed run retries backup and exits. A mismatched saved source/config/data/environment identity stops rather than interpreting a checkpoint under different training semantics.
12. `stage_init_run` seeds a new epoch from a verified, **completed** prior run. It copies final adapter weights and compatible cache evidence, then resets optimizer/schedule. Ordinary `resume_from_checkpoint` within an interrupted run restores the full state instead.

## Changes for this dataset

The new folder copies the active training/storage/recovery implementation so it remains independently runnable when uploaded alone. The training module and config are renamed, source capture includes the new loader, and cache compatibility references the new training filename. ASLP files were not edited.

Only the input preparation and launch defaults change: the pinned `kaab4321/UrduTTS` saved-Arrow release supplies embedded audio and `transcription`; `eval` maps to validation; no test download or unverified speaker identity is needed. `urdutts_data.py` converts to the exact existing manifest/audio contract. Local shard completion records verify converted WAVs on restart. Source read failures trigger bounded transfer retries; invalid source rows are recorded separately from later audit/encoding exclusions. Disk and network errors are not classified as bad clips.

The new notebook sets `INIT_FROM_RUN=None`, uses the original base with LR 1e-4, isolates UrduTTS run/work/repository names, supports either a monorepo subfolder or a standalone repository, and starts with `TEST=True` for 20/10 source examples. The smoke run cannot overwrite or initialize the full run. The original one-epoch schedule and additional-epoch semantics are retained.

## Evidence and remaining checks

The public Hub tree, `dataset_dict.json`, `train/state.json`, dataset metadata, dataset card, and an actual Arrow stream schema were inspected. Actual fields are `audio: struct<bytes: binary, path: string>`, `transcription`, `roman`, `phonemes`; splits are train/eval/test. The repository contains 41 train, 12 eval and 6 test shards. The dataset viewer's config-info job was failing when inspected, another reason not to depend on viewer APIs or assume a standard Parquet `load_dataset` release.

CPU tests cover token ranges, data auditing, storage snapshot verification and atomic publication, failed commits, local/remote restoration, optimizer-state completeness, source identity, disk recovery, upload retries, memory selection, monitoring failures, adapter export, and new-epoch seeding. New tests cover embedded-audio Arrow streaming, native-rate/stereo conversion, Urdu-text selection, split mapping, avoiding test requests, bounded smoke input, separate smoke/full caches, corrupt WAV rebuilding and invalid config/source handling. Training tests mock GPU libraries; they establish control flow, not CUDA numerical correctness.

A live public-data check successfully converted and audited 20 train and 10 eval examples with no row exclusions (about 0.03104 and 0.01582 hours respectively). No raw source Arrow files were stored in the project. Full-corpus conversion, CUDA setup/training, authenticated private Hub transfers, runtime duration, VRAM sufficiency and perceptual Urdu quality remain to be checked in Kaggle. The notebook's smoke check requires finite validation loss and remote checkpoint durability before it reports success.
